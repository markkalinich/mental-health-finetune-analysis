## yavuz-ai/qwen3-4b-cai-sft

### Sources

The training script and the writeup are one project, [shipbehaves/constitutional-cai](https://github.com/shipbehaves/constitutional-cai). The model card text is the same file as `cards/cai-sft.md` in that repo. Featherless repeats the card. Bai et al. 2022 is the method being copied. It is not a paper about this checkpoint. No independent third-party training report was found.

Cached card: `revision_3_experiments/hf_inventory/cache/readmes/yavuz-ai__qwen3-4b-cai-sft__2026-10-06.md`.

The repo name contains `sft` and `cai`. Those words are also stated in the card and the script, so they are not only a name.

### Training record

**(a) Objective.** Supervised next-token fine-tuning on revised answers. Not DPO and not RLHF. The DPO stage is a different Hub repo.

Card says: "The supervised stage of a Constitutional AI reproduction" and "LoRA SFT, merged." ([cached card](revision_3_experiments/hf_inventory/cache/readmes/yavuz-ai__qwen3-4b-cai-sft__2026-10-06.md))

Script says: "SL-CAI stage: LoRA SFT on the filtered self-revisions" and `trainer = SFTTrainer(...)` with `completion_only_loss=True`. (https://github.com/shipbehaves/constitutional-cai/blob/main/src/train_sft.py)

README says: "Supervised fine-tune on the revised answers." The next stage, which this checkpoint is not, is "Those AI-labeled preferences train the policy with DPO." (https://github.com/shipbehaves/constitutional-cai/blob/main/README.md)

**(b) Parameter-update scope.** LoRA, then merged into the uploaded weights.

Card says: "LoRA SFT (r=16, alpha=32, all-linear)".

Script says: `LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, bias="none", task_type="CAUSAL_LM", target_modules="all-linear")`, then `merged = trainer.model.merge_and_unload()` and `merged.push_to_hub(OUTPUT_REPO)`. Dropout 0.05 is in the script and not on the card.

Hub API for this repo: `library_name` transformers, relation `finetune`, one `model.safetensors`, 4,022,468,096 BF16 parameters, no `adapter_config.json`. (https://huggingface.co/api/models/yavuz-ai/qwen3-4b-cai-sft) That count matches the base `Qwen/Qwen3-4B-Instruct-2507`.

**(c) Training data.** Prompts are the first human turn of `Anthropic/hh-rlhf` `harmless-base/train.jsonl.gz`. Targets are this model's own revised answers. The filtered training file is the dataset `yavuz-ai/cai-sft`.

Script `cai_generate.py` says the default model is `Qwen/Qwen3-4B-Instruct-2507`, and the SL path is answer, then critique, then revise, at temperature 0. (https://github.com/shipbehaves/constitutional-cai/blob/main/src/cai_generate.py)

`cai_filter.py` writes prompt/completion rows and uploads them to `yavuz-ai/cai-sft`. `train_sft.py` loads that dataset. (https://github.com/shipbehaves/constitutional-cai/blob/main/src/cai_filter.py)

Card says: "Data: ~4,800 self-revisions generated from hh-rlhf harmless-base prompts."

Datasets-server says `yavuz-ai/cai-sft` has 4,804 train rows. (https://datasets-server.huggingface.co/size?dataset=yavuz-ai/cai-sft)

Provenance: the prompts are human red-team text from hh-rlhf. The revisions are synthetic, generated by `Qwen/Qwen3-4B-Instruct-2507` itself. Five principles are hard-coded in `cai_generate.py`. The card says they are "adapted from public sources (the CAI paper and Anthropic's published constitution)."

Language: not stated anywhere found in the card or the scripts.

**(d) Base.** `Qwen/Qwen3-4B-Instruct-2507`. The Qwen card says: "We introduce the updated version of the **Qwen3-4B non-thinking mode**, named **Qwen3-4B-Instruct-2507**" and "Training Stage: Pretraining & Post-training". (https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) That is the post-trained instruct checkpoint, not a pretrain-only base.

**(e) Hyperparameters.** Card says: "2 epochs, lr 1e-4, bf16, on 1x A100."

Script defaults, which the card matches and which the documented run does not override: `num_train_epochs` 2, `learning_rate` 1e-4, `per_device_train_batch_size=4`, `gradient_accumulation_steps=4` (the comment says effective batch 16), `max_length=1024`, cosine schedule, `warmup_ratio=0.05`, `seed=42`, bf16 on CUDA. Hardware in the card is 1x A100. The script's run line uses Hugging Face Jobs flavor `a100-large`.

**(f) Evaluation.** README says, for this checkpoint versus the base: safe on harmful prompts 0.989 to 1.000, over-refusal on benign prompts 0.327 to 0.431. Safety judge is IBM Granite Guardian. Over-refusal is refusal detection. Held-out sets named: StrongREJECT and hh-rlhf harmless-base test for safety; XSTest-safe and OR-Bench-hard for over-refusal. (https://github.com/shipbehaves/constitutional-cai/blob/main/README.md)

**(g) Output.** A chat reply. The training target is a revised answer to the user prompt, including refusals of harmful requests. It is not trained to emit a safe/unsafe label.

This agrees with the earlier row: user prompt, chat reply, more refusals.

### Discrepancies

1. Inventory `methods` is `lora|rlhf|sft`. The `rlhf` hit is the dataset string `Anthropic/hh rlhf` and the tag `rlaif` (`kept.csv` `method_evidence`). This checkpoint's card and `train_sft.py` state LoRA SFT only. The preference stage is `yavuz-ai/qwen3-4b-cai-rlaif` and `yavuz-ai/qwen3-4b-cai-rlaif-v2`, which list this repo as their base.

High. The card, the SFT script, and the dataset row count agree, and the script states the merge.

## tomg-group-umd/DynaGuard-8B

### Sources

Paper: Hoover et al., DynaGuard: A Dynamic Guardian Model With User-Defined Policies. Preprint https://arxiv.org/abs/2509.02563. The arXiv source (`main.tex`, fetched from https://export.arxiv.org/src/2509.02563) is what marks the chosen learning rates in bold. The same work is in the ICLR 2026 proceedings: https://proceedings.iclr.cc/paper_files/paper/2026/file/8d2aad53fa148791ffd004a7c9cce5ad-Paper-Conference.pdf.

The model card repeats the training sentence and cites the paper. It is not an independent source. GitHub https://github.com/montehoover/DynaGuard contains evaluation code (`eval.py`, `ifeval.py`, prompts). It has no training script. A search of `main.tex` finds no LoRA, QLoRA, or full-parameter sentence.

The 1.7B and 4B models use the same written recipe. The size-specific numbers below are the 8B rows. Ablation Tables 4 and 5 in the paper are Qwen3-4B runs, not the 8B checkpoint.

Cached card: `revision_3_experiments/hf_inventory/cache/readmes/tomg-group-umd__DynaGuard-8B__2026-10-06.md`.

### Training record

**(a) Objective.** Supervised fine-tuning, then GRPO. GRPO is reinforcement learning with a scalar reward. The paper does not name DPO, PPO, or a separate reward model.

Paper says: "The first stage of our training pipeline is supervised fine-tuning over a mixture of 40,000 samples from DynaBench and 40,000 samples from the four safety datasets (WildGuard, BeaverTails, ToxicChat, and Aegis 2.0). We run SFT for 1 epoch, followed by GRPO using 11,000 samples from the data mixture." (https://arxiv.org/html/2509.02563, section 3.4)

The SFT loss is next-token log probability of the compliance label, and, for one third of the rows, of a thinking trace plus the label (equations 1 and 2, called C-SFT and CT-SFT).

The GRPO objective (equation 3) uses advantage from a scalar reward. Paper says: "Here, R(r,x,t,y) denotes the scalar reward assigned by the evaluator to the model’s generated thinking trace t and compliance label y". What that evaluator scores is not stated anywhere found.

Card says: "The model was trained using Supervised Fine-Tuning (SFT) for one epoch, followed by GRPO."

**(b) Parameter-update scope.** Not stated anywhere found. The paper says the trainer is VERL: "We used the training framework VERL Sheng et al. [2024] for both SFT and GRPO." VERL can train all weights or LoRA. This paper does not say which. LoRA rank, alpha, and target modules: not stated. Whether an adapter was merged: not stated.

The Hub release is a full checkpoint, not an adapter repo. Cached Hub metadata: `library_name` transformers, `base_model:finetune:Qwen/Qwen3-8B`, BF16. (`revision_3_experiments/hf_inventory/cache/cards/2026-10-06__000.csv`) That does not say whether training updated every weight.

**(c) Training data.** SFT: 40,000 DynaBench samples plus 40,000 samples from WildGuard, BeaverTails, ToxicChat, and Aegis 2.0. GRPO: 11,000 samples from that mixture. The results text says the recipe that did best is "SFT + GRPO on a 50/50 mixture of Safety data and DynaBench." The 40k + 40k split is that 50/50 mix. The appendix grid also tried 67/33 and 33/67. The source does not bold a mix, but the body states 50/50 as the recipe used.

Only DynaBench has a Hub id on the card: `tomg-group-umd/DynaBench`. Hub ids for the four safety sets: not stated anywhere found.

DynaBench construction, paper section 3: about 500 hand-written rules, expanded with GPT-4o, Gemini-2.0-Flash, and Claude Sonnet 3.5 to 5,000 rules, then paraphrased into 40,000 policies. Dialogues are generated by GPT-4o-mini and GPT-4.1-mini. Labels and reasoning traces are generated by GPT-4o and Gemini-2.0-Flash. The paper also says the train set is 61,500 samples and the test set is 543 examples. Training uses 40,000 of the DynaBench samples, not the whole 61,500. A human check of 743 train rows is reported (Cohen's kappa 0.85 against the synthetic labels). The test policies are described as hand-written with LLM help on the dialogues.

Language: the card YAML says `language: en`.

**(d) Base.** `Qwen/Qwen3-8B`. Paper says: "We use the Qwen3 family of instruction models (Yang et al., 2025)" and "the Qwen3 instruct model that we finetune from." The Qwen card for `Qwen/Qwen3-8B` says "Training Stage: Pretraining & Post-training". The separate repo `Qwen/Qwen3-8B-Base` says "Training Stage: Pretraining". (https://huggingface.co/Qwen/Qwen3-8B, https://huggingface.co/Qwen/Qwen3-8B-Base) The 8B base is the post-trained instruct checkpoint.

**(e) Hyperparameters, 8B row.** Appendix A.9. Shared settings are one row for all three sizes. Only the learning rate is split by size.

arXiv `main.tex` (bold is the value they say they used):

- SFT learning rate (8B): `7e-6, \textbf{1e-5}, 3e-5`. Chosen: 1e-5.
- SFT batch size, all sizes: `64, \textbf{128}, 256`. Chosen: 128.
- GRPO learning rate (8B): `7e-7, \textbf{1e-7}, 3e-7`. Chosen: 1e-7.
- GRPO batch size, all sizes: `32, \textbf{48}, 64, 128, 256`. Chosen: 48.
- GRPO rollouts, all sizes: `\textbf{8}, 12, 16`. Chosen: 8.

Also stated, not as a grid: SFT and GRPO use a cosine schedule, gradient clipping 1.0, weight decay 1e-2. GRPO KL coefficient 1e-3, response length 1024, temperature 1.0, top-p 1.0. SFT is 1 epoch. GRPO is 11,000 samples, not an epoch count. They say validation plateaued at 11k and they did not use the 13k or 15k GRPO checkpoints.

Hardware: not stated anywhere found.

The ICLR 2026 PDF lists the same SFT 8B candidates (`7e-6, 1e-5, 3e-5`). Its GRPO 8B line is different: `7e-7, 1e-6, 3e-6`. `pdftotext` does not show which of those three is bold.

**(f) Evaluation.** Paper Table 3, F1 percent. DynaGuard-8B without chain-of-thought: Aegis 2.0 78.9, BeaverTails 83.6, HarmBench 87.1, Safe-RLHF 64.4, WildGuard 79.3, XSTest 88.2, DynaBench 72.5, safety average 79.6, all-tasks average 78.4. DynaGuard-8B with chain-of-thought: 80.5, 84.7, 87.0, 67.3, 80.8, 89.6, 73.1, safety average 81.1, all-tasks average 79.7. The untuned `Qwen3-8B` row is DynaBench 60.7 and safety average 68.8. Section A.8 is an 8B-only IFEval check: of 232 Ministral-8B instruction failures, DynaGuard flagged 157, and the explanations led to 32 corrected answers.

The card's table matches the paper's DynaBench and safety-average numbers (72.5 / 79.6 and 73.1 / 81.1). It does not print the all-tasks average.

**(g) Output.** A verdict. The input is a natural-language policy plus a dialogue. The output is `PASS` or `FAIL`, either after a `<think>` trace or directly inside `<answer>`, with a short `<explanation>` on the fast path. It is built to detect any violation of the policy in the dialogue, including rules that are not a fixed harm list (refunds, format rules, and the usual safety categories when those are written as the policy).

This agrees with the earlier row: prompt and reply in, binary label out, judgment training. The explanation is text attached to the verdict, not a chat reply to the end user.

### Discrepancies

1. arXiv source bolds GRPO 8B learning rate 1e-7 inside the grid `7e-7, 1e-7, 3e-7`. The ICLR 2026 PDF prints `7e-7, 1e-6, 3e-6` and does not show bold.
2. Inventory `datasets` is only `tomg-group-umd/DynaBench`. The card and the paper also name WildGuard, BeaverTails, ToxicChat, and Aegis 2.0.

### Confidence

High for the objective, the 80,000 / 11,000 split, the base, and the output. The chosen GRPO 8B learning rate is the weak point, because the preprint source and the proceedings PDF do not print the same grid. Parameter-update scope is not stated.

## Hari5115/MoleculeIQ-SmolLM2-360M

### Sources

No paper, GitHub repo, blog, or training script was found for this checkpoint. Searches for the repo id, "MoleculeIQ", the author name Hariprasad Sundaresan, and `SFTTrainer` returned the model card, the dataset card, the author's Hugging Face page, and an unrelated MolecularIQ benchmark from JKU (arXiv 2601.15279). That benchmark is a different project.

The model card and the dataset card are both written by Hari5115. They are not copies of each other. They disagree on counts and on how duplicates were removed.

Cached card: `revision_3_experiments/hf_inventory/cache/readmes/Hari5115__MoleculeIQ-SmolLM2-360M__2026-10-06.md`.

The repo name does not contain `sft`. The tags contain `lora` and `peft`. The card also states LoRA, so the tag is not the only evidence.

### Training record

**(a) Objective.** Not stated anywhere found. The card says the model was "fine-tuned" and "Fine-tuning method | LoRA via peft", and the credits line says "Fine-tuning: trl + peft". It never says SFT, next-token loss, DPO, ORPO, or a reward. `trl` includes more than one trainer. The loss is not named.

**(b) Parameter-update scope.** LoRA, as stated. Rank 16, alpha 32, dropout 0.05, target modules `q_proj, k_proj, v_proj, o_proj`, trainable parameters 3,276,800 (0.90% of the total). No 4-bit base is mentioned, so this is not described as QLoRA.

Whether the adapter was merged: not stated anywhere found.

The uploaded repo does not contain `adapter_config.json` or `adapter_model.safetensors`. Hub API siblings are `model.safetensors` with 361,821,120 float32 parameters. `library_name` is `peft` and the base relation tag is `adapter`. The card's example loads `AutoModelForCausalLM` on this repo id, not `PeftModel`. (https://huggingface.co/api/models/Hari5115/MoleculeIQ-SmolLM2-360M) A 3.3M-parameter adapter would not be a 362M-parameter float32 file. The release is a full weight file. No source says those weights were produced by merging the adapter.

**(c) Training data.** Card says the training set is `Hari5115/MoleculeIQ`, "3,627 Q&A pairs across 268 molecules", "Training examples | 3,082", "Generated via Claude Haiku API", "Deduplicated using semantic similarity (sentence-transformers)". Language YAML: `en`.

Datasets-server row counts for `Hari5115/MoleculeIQ`: 3,627 rows total, train 3,082, test 545. (https://datasets-server.huggingface.co/size?dataset=Hari5115/MoleculeIQ) Those two counts match the model card. The dataset card's prose does not: it says "~5,000 Q&A pairs", train "~4,250", test "~750". (https://huggingface.co/datasets/Hari5115/MoleculeIQ)

Dataset card says: "Generated using Claude claude-haiku-4-5-20251001 (Anthropic)" and "deduplicated using TF-IDF cosine similarity (threshold 0.85)". The model card says sentence-transformers, not TF-IDF, and it does not name the Haiku snapshot.

The dataset viewer lists 253 distinct `molecule` values. The model card says 268 molecules. The viewer also has a `safety_level` field. No source says the model was trained to emit that field. The card's target is a prose answer.

**(d) Base.** `HuggingFaceTB/SmolLM2-360M-Instruct`. The SmolLM2 card says: "We developed the instruct version through supervised fine-tuning (SFT) using a combination of public datasets and our own curated datasets. We then applied Direct Preference Optimization (DPO) using UltraFeedback." (https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct) The base is the instruct checkpoint, not `HuggingFaceTB/SmolLM2-360M`.

**(e) Hyperparameters.** Card table: learning rate 2e-4, cosine schedule, effective batch size 32, 3 epochs, max sequence length 768, about 17 minutes on a T4 GPU. Per-device batch size: not stated.

**(f) Evaluation.** Card says 200 held-out examples from the MoleculeIQ test split. ROUGE-L 0.1349 to 0.1697. BERTScore F1 0.7835 to 0.8096. The comparison column is labeled "Base SmolLM2-360M", not the Instruct id used as the training base. The test split has 545 rows, not 200.

**(g) Output.** A chat reply. Card says: "the model explains whether it is safe, how it works in the body, and what precautions to take — in plain English, always leading with the conclusion." It is not built to emit a safe/unsafe label. The questions are about food additives, cosmetics, household chemicals, medications, environmental chemicals, and natural compounds.

This agrees with the earlier row: a narrow-domain question, a chat reply, a different skill from refusal training.

### Discrepancies

1. Dataset card prose says about 5,000 pairs, about 4,250 train, about 750 test. The parquet counts are 3,627, 3,082, and 545. The model card matches the parquet counts.
2. Model card says deduplication with sentence-transformers. Dataset card says TF-IDF cosine similarity at 0.85.

4. Model card says 268 molecules. The dataset viewer lists 253 distinct molecule strings.

6. Card and Hub tags say LoRA / peft / adapter. The file list is a full `model.safetensors` (361,821,120 float32 parameters) and no adapter file. Merge is not stated.

### Confidence

Medium. The LoRA settings and the 3,082-row train count are stated on the card and the train count matches the files. There is no script, the loss is unnamed, and the dataset card disagrees with the files and with the model card.

## Patterns in this batch

These three checkpoints are three different training jobs that all got a safety tag. One is a chat model whose supervised stage copies Constitutional AI: LoRA on its own revised answers, then the adapter is merged. The preference-optimization stage exists, but it is a later repo, so an `rlhf` label on this checkpoint is the dataset name, not the method. One is a guardian that prints PASS or FAIL. The paper is explicit that training is one epoch of supervised fine-tuning and then GRPO, and it gives an 8B learning rate, but it never says whether every weight was updated. One is a 360M LoRA fine-tune that answers ingredient questions in prose. The card gives rank, alpha, and target modules, and it never names the loss. Only the guardian has a paper. The other two depend on the author's card or script, and MoleculeIQ's dataset card does not match its own files.
