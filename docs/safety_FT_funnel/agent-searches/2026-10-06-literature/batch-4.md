## 1. ReasoningShield/ReasoningShield-3B

The training method is in the arXiv paper, including Appendix G. The GitHub repository ships the data files and the inference scripts. It does not ship a training script. The model card repeats the stage sizes, epochs, and batch size, and does not print the learning rates.

### Sources

- Cached card, 2026-10-06: `revision_3_experiments/hf_inventory/cache/readmes/ReasoningShield__ReasoningShield-3B__2026-10-06.md`. Live page: https://huggingface.co/ReasoningShield/ReasoningShield-3B . Created 2025-05-20, last modified 2025-09-27. Names this repo id.
- Preprint, arXiv 2505.17244, HTML retrieved 2026-10-06: https://arxiv.org/html/2505.17244 and https://arxiv.org/abs/2505.17244 . Authors: Changyi Li, Jiayi Wang, Xudong Pan, Geng Hong, Min Yang. `CITATION.cff` in the GitHub repo calls the same text a NeurIPS 2026 paper and points at that arXiv URL: https://raw.githubusercontent.com/CosmosYi/ReasoningShield/main/CITATION.cff . The proceedings PDF was not fetched separately.
- GitHub tree: https://github.com/CosmosYi/ReasoningShield . The tree has inference scripts under `reasoningshield/` and the train CSVs `reasoningshield_Dataset/reasoningshield-train/stage1_sft.csv` and `stage2_dpo.csv`. No `train.py`. README links https://huggingface.co/ReasoningShield/ReasoningShield-3B .
- Dataset card: https://huggingface.co/datasets/ReasoningShield/ReasoningShield-Dataset . Same authors' dataset. It restates the paper's split. It is not an independent training log.
- Hub API: https://huggingface.co/api/models/ReasoningShield/ReasoningShield-3B . Safetensors: 3,212,749,824 parameters, BF16. Siblings are two weight shards and `model.safetensors.index.json`. No `adapter_config.json`. Tag `base_model:finetune:meta-llama/Llama-3.2-3B-Instruct`.

### Training record

**(a) Objective.** Two stages. Paper says: "we perform Supervised Fine-Tuning (SFT) on the base model" and prints the loss as the log probability of the analysis and the judgment given the prompt, the query, and the reasoning trace: "L_SFT = -E log P_theta(A, J | I, Q, y_CoT)". That is supervised next-token training. Stage 2, paper says: "We further refine M_SFT via Direct Preference Optimization (DPO) (Rafailov et al., 2023)". Appendix G.1 says stage 2 is "full-parameter DPO training" in LlamaFactory. The arXiv HTML prints equation (4) as a sigmoid of a score difference. Beta is not stated anywhere found. The GitHub README summary says the second stage "uses contrastive learning". The same README's dataset section says "DPO Subset: 2,642 hard negative samples".

**(b) Parameter-update scope.** Paper, Appendix G.1: "in stage 1, the model undergoes full-parameter fine-tuning on the 4,358 agreed-upon samples". Stage 2 is "full-parameter DPO training". Card says: "Stage 1: Full-parameter Fine-tuning" and "Stage 2: Direct Preference Optimization Training". LoRA rank, alpha, and target modules: not stated anywhere found. No adapter file is in the repo. The uploaded parameter count is the full 3.2B Llama in BF16.

**(c) Training data.** Hub id `ReasoningShield/ReasoningShield-Dataset`. Paper and card: 7,000 (query, chain-of-thought) pairs, split into 4,358 agreed-on samples and 2,642 hard-negative pairs. Language on the model card: English. Paper says train queries come from AIR-Bench, SALAD-Bench, and Alpaca. Dataset card says the training traces "are generated using" QwQ-32B, DeepSeek-R1-32B, DeepSeek-R1-8B, and OpenThinker-7B: https://huggingface.co/datasets/ReasoningShield/ReasoningShield-Dataset . Paper says the train labels come from a vote of Qwen2.5-72B-Instruct, Mistral-Small-3.1-24B-Instruct, and Gemma-3-27b-it. Full agreement becomes the supervised set. Partial agreement becomes the preference set. "single-vote cases are relabeled by human experts." The preference fields are named on the dataset card: `chosen` is the preferred analysis, `rejected` is the other one.

**(d) Base model.** Card YAML and Hub tag: `meta-llama/Llama-3.2-3B-Instruct`. That id is Meta's instruction-tuned 3B checkpoint. Paper says: "We select Llama-3.2-1B and Llama-3.2-3B (Meta, 2024a) as the base models". The paper sentence does not contain "Instruct".

**(e) Hyperparameters.** Appendix G.1 and Table 11, applied to the 1B and 3B runs together: stage 1, batch size 2, gradient accumulation 8, learning rate 1e-5, cosine schedule, 3 epochs, bf16, warmup ratio 0.1. Stage 2, learning rate 2.0e-6, 2 epochs, "other settings remain consistent with Stage 1". Hardware: "8 NVIDIA A800-SXM4-80GB GPUs" on Ubuntu 22.04, framework "LLamaFactory". The 10-minute and 12-minute runtimes in that appendix are "Taking the 1B model as an example". They are not stated for the 3B file. The card prints the same batch size, accumulation, epochs, and bf16, and does not print the learning rates.

**(f) Evaluation.** Paper and card Table: ReasoningShield-3B average F1 91.8 on open-source reasoning-model traces and 81.4 on closed-source traces, across AIR, SALAD, BeaverTails, and Jailbreak. Paper also reports an ablation on the 3B comparison table's family: SFT+DPO CoT accuracy 87.0 and F1 86.3, versus SFT-only 77.1 and 76.8. The answer-moderation bar chart is in the card and the paper. The GitHub eval script writes an analysis column and a judgment column.

**(g) Output and what it detects.** It judges another model's reasoning trace, not the end user's question. Card: "identify hidden risks in intermediate reasoning steps". The prompt in the paper's appendix requires an "Analysis" and a "Judgment" of 0, 0.5, or 1 (safe, potentially harmful, harmful), over 10 risk categories plus "Other Risks". It detects harmful content hidden inside a reasoning trace. It is not built to answer the query.

Hand classification (`docs/safety_FT_funnel/how-models-are-filtered.md`): input "assistant reply", output "reasoning and a verdict", goal "judgment training". That matches this reading. In the summary table the output type is `verdict`.

### Discrepancies

1. The paper names the base as Llama-3.2-3B. The card, the Hub tag, and the inventory parent are `meta-llama/Llama-3.2-3B-Instruct`.
2. The GitHub README summary says "contrastive learning". The paper, Appendix G.1, the dataset card, and the model card say DPO. The same README also labels the second file "Stage 2 DPO data".
3. The card does not print the learning rates that Appendix G.1 prints (1e-5, then 2e-6).
4. A survey (https://arxiv.org/pdf/2509.03871) says ReasoningShield "finetuned Llama-3.2" on "8k prompt-CoT pairs" with SFT on agreed samples and DPO on hard samples. The paper's count is 7,000. The survey is a paraphrase, not a second training log.

### Confidence

High. The paper, the dataset card, the model card, and the released CSV names agree on supervised fine-tuning of all weights, then full-weight DPO, on 4,358 and 2,642 samples. The open gap is the paper's base-model name, which omits "Instruct".

### Training record

**(a) Objective.** Not stated anywhere found. The card says "Method: QLoRA" and "Training data: 840 chain-of-thought examples". The name contains "cot" and "modal". It does not state a loss, and the file was not found.

Whether the adapter was merged: not stated anywhere found.
