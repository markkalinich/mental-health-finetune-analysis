## Record

The card says the training set is 19,576 rows from 11 files. The base file is `v1.6.0_train.jsonl`, 9,657 rows, "Base safety classification (Aegis 2.0, HH-RLHF, Dolly, OASST1)." The card does not say how many of those 9,657 rows come from each source. The other files are v1.6b 604, v1.6c 2,000, v1.6d 1,660, v1.6e 2,000, v1.6e2 2,000, v1_6e7_FPonly 1,005, v1_6g_fpfix 300, v1_6h_ip_fix 100, v1_6i_edu_style_fix 170, and v1_6j_pers_tag_fix 80. Only the g, h, and i files are in `tzchen07/rai-safety-campaign-2026`. That dataset's viewer is off, so those files do not load as a Hub dataset. The card calls the g file "Synthetic FP-fix." It does not say whether h or i are synthetic. The other eight files are not on the Hub.

Aegis 2.0 is `nvidia/Aegis-AI-Content-Safety-Dataset-2.0`. It loads. The dataset card says 33,416 annotated interactions. Provenance is mixed: human prompts from Anthropic HH-RLHF and responses from Mistral-7B-v0.1. Language is English. HH-RLHF is `Anthropic/hh-rlhf`. It loads, 169,352 rows. The card says "Human preference data about helpfulness and harmlessness." Provenance is human. Dolly is `databricks/databricks-dolly-15k`. It loads, 15,011 rows, English. The card says the records were "generated by thousands of Databricks employees," so the provenance is human. OASST1 is `OpenAssistant/oasst1`. It loads, 88,838 rows. The card says it is "a human-generated, human-annotated assistant-style conversation corpus consisting of 161,443 messages in 35 different languages."

The objective is supervised fine-tuning. The card says "Single-stage DoRA SFT." The update is DoRA, which is weight-decomposed LoRA, not standard LoRA. The card says "LoRA: DoRA (Weight-Decomposed), r=64, alpha=128." `adapter_config.json` has `use_dora` true, `peft_type` LORA, rank 64, and alpha 128. One epoch. Learning rate 1e-4. Batch 4 per device with gradient accumulation 16, effective batch 64. Precision bf16, so the base was not quantized during training. Step count is not stated. The published weights are merged. The title says "Merged," and the root file is `model.safetensors`. The adapter is also in `lora_adapter/`. The campaign script `train_g4_DPO_full.py` is full-parameter DPO for a different run name, `g4_X9e2_v16f_x3_fullSFT_dpo`. It is not the recipe this card states for this checkpoint.

The parent is `google/gemma-4-E2B-it`. The card and the adapter config agree. The card says "5.2B params." The Hub safetensors count is 5,031,228,707. The card does not name a language. License Apache-2.0.

This is a classifier. The card says "enterprise content safety classifier." The input is one user request, written as `{'request': '<query>'}`, plus a system string the card writes as `<v3.1 safety policy>`. The full policy is `prompts/v3_1_VerdictReason.jinja`. It says "Determine whether a user query should be filtered for unsafe content." The trained output is two lines, a verdict and a reason. Production serving sets `stop=["Reason:"]`, so the returned text is the verdict line: "Verdict: none" or "Verdict: Self-harm". The jinja names 13 categories: Violence/Harassment, Hate/Discrimination, Misinformation, Sexual Content, Illegal Activity, Self-harm, Jailbreak/PromptInjection, Intellectual Property, PII, Politics, Impersonation, Specialist Advice, and High-risk decisions. `none` is the safe verdict.

Serving in the card's example is text. The example uses temperature 0.0 and max_tokens 50. `config.json` sets context to 131,072. The vLLM command uses `--max-model-len 8192`. The saved chat template is the Gemma template, not the safety policy. The Gemma 4 technical report does not print this repository id. No GitHub repository names this checkpoint.

VerdictReason on the card's v14 set has block rate 0.050% (3 / 5,896). On v200 it has precision 1.0000, recall 0.2270 (227/1000), and F1 0.3702.
