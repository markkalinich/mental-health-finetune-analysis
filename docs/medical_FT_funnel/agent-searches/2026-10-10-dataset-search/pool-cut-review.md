# Review of the medical dataset-search pool cut

Reviewed against the code and the 2026-10-10 cache. Python was `/home/mkalinich/main/.venv/bin/python`. No code or data file was edited.

## (a) Verdict

The cut is sound with changes. The premise is true: a dataset found by the search cannot give a model a parent, and a model with no parent in the card cannot pass step 3. The six counts match the cached cards. The proposed way of drawing the pool does not. `funnel.py --grouping medical --relax dataset` writes a sensitivity run whose step-3 survivors are every non-vision model that already clears step 3, datasets included. Of the 987 models in the proposer's remainder, 2 already have the parent card, both configs, and a passing step-3 result. The other 985 are cache misses or later step-3 checks, so they are not survivors until those files are fetched. Taking survivors as the pool, on the cache as it is, searches models that already named a dataset and drops almost every `no_dataset` model the cut was meant to keep. Three further changes are required before that survivor list is the pool: intersect it with `no_dataset` and with the text-generating rule; fetch the missing parent cards and configs (safe on 2026-10-10); and do not let the regex class drop a child whose parent is still absent from `parents.csv`. The funnel's own weight check is the right quantized-parent test, except for seven children of Qwen3.5, whose root shards are full precision and whose filenames the root-file rule does not recognize.

## (b) Findings

1. **A dataset search cannot supply a parent. Severity: note. The claim checks out.** `rules.extract_parent` (`rules.py` 363–413) reads only the Hub `baseModels` field, the card YAML `base_model`, and `base_model:` tags. `funnel.py` `parent_checks` (471–473) calls that and nothing else. The dataset-search prompt's CSV columns (`agents/PROMPT-dataset-search.md` 65–66) are dataset fields. `merge_dataset_search.py` (9–10), `select_admissions.py`, and `admit_recovered.py` (27, 72–73) never write a parent. `accessible_data.csv` columns are `grouping, hf_id, decided_on, data_name, access_url, access` (`funnel.py` 59). `dataset_aliases.csv` rewrites a dataset name (`funnel.py` 366–380). `--relax dataset` does not switch on `--relax parent`, which is the only mode that lets `no_parent` through (`funnel.py` 100, 407–409). A model whose card has none of those three parent fields stops at step 3 as `no_parent`.

2. **The quantized-parent cut matches the funnel for every parent card already cached. The name regex is only an estimate. Severity: note for the estimate; the pool must use the funnel's weight check.** Step 3 calls `precision` on the named parent's own card (`funnel.py` 476–488) and returns `parent_not_fp` for every verdict other than `keep`, `row_unreadable`, and a missing header. `parents.csv` `base_repo` is loaded (`funnel.py` 70, 194–200) and never read. `build_parents.py` 23–25 copies the original's class onto a rehost row at registry-build time; the funnel still weight-checks the rehost id. Five registry rows are `instruction` and have a quantization marker in the id (`unsloth/Meta-Llama-3.1-8B-Instruct-bnb-4bit` and four other `bnb-4bit` rows). Each has `base_repo` set to the full-precision original, and each cached card is `other_dtype` (`BF16|F32|U8`). They fail step 3. The 675 name matches are 81 parent repos: 34 have a cached card and all 34 are `other_dtype`; 47 have no card, so those children are unverified. No cached card is a false name match. The regex misses `openai/gpt-oss-20b` (3 children in the 987): root shards match the filename rule, and the dtype summary is `BF16|U8`, so the funnel returns `other_dtype`. Use the funnel's check for the pool. Keep the regex only as the planning estimate the proposal already intends to replace.

3. **Registry class is final for this run, and the date filter changes nothing. Severity: note. The claim checks out.** A `parents.csv` row overrides the regex (`funnel.py` 493–502). `load_parents` keeps rows with `decided_on` on or before `--as-of` (`funnel.py` 186–187, 194–196). All 251 rows are `decided_on` 2026-10-09, which is on or before 2026-10-10. Classes on file: instruction 102, pretrained 71, finetune 51, not_a_language_model 25, unreadable 2. The funnel also drops `unreadable` (`PARENT_CLASS_REASON`, `funnel.py` 117–124). None of the 987 has a parent registered as `unreadable`, so the proposer's three-class cut of 63 is complete for this pool. It is 58 pretrained, 4 finetune, and 1 not_a_language_model.

4. **`--relax dataset` does not produce the search pool. Severity: blocks.** What the flag changes is narrow and correct. `RELAX["dataset"]` (`funnel.py` 93–95) skips the `no_dataset` stop and the Hub-exists check (`funnel.py` 384–402). The vision/video stop still runs first (`funnel.py` 381–382). Step 1 is unchanged. Step 3, including the config comparison (`funnel.py` 412–427), does not look at whether a dataset was named. Nothing in step 3 runs only when a dataset is present. Results go to `results/medical/sensitivity/2026-10-10__relax-dataset/` (`funnel.py` 605). `results/medical/CURRENT` is updated only when `--relax` is absent (`funnel.py` 640–644).

   The survivor set is still the wrong pool. Survivors are every cohort model that passes step 1, is not vision/video, and passes step 3. That includes models that already named a dataset and models at `dataset_not_on_hub` (252 in `results/medical/2026-10-10/counts.csv`). It includes token-classification and other non-generating pipelines, because `VISION` (`rules.py` 51) is only four image/video tags. It does not apply `make_pool.py`'s text-generating rule (pipeline tag in `text-generation`, `image-text-to-text`, `text2text-generation`, or an untagged causal-LM architecture; `make_pool.py` 4–7 and 37). And a model whose step-3 files are not cached stops as `missing:*`, which is not a survivor.

   On the current cache, 2 of the 987 would be survivors: `stravoris/medmcq-psychiatry-classifier-qwen3-0.6b` (parent `Qwen/Qwen3-0.6B`) and `stravoris/medmcq-psychiatry-qwen3-1.7b` (parent `Qwen/Qwen3-1.7B`). Both are registered instruction parents, both configs exist, and `parent_discordant` returns `keep`. The other 985 are not evaluable or fail a check that needs those files. 749 of the 751 tagged text-generating models in the 987 have no child `config.json`. They stopped at step 2 in the normal run, so step 3 never asked for one (`funnel.py` 384–386 returns before 419).

   What to change: run `--relax dataset` so the funnel's own checks run, then take the intersection of (normal-run `decision == no_dataset`) and (text-generating, after the untagged config fetch `make_pool.py` already requires) and (relaxed-run step greater than 3). `make_dataset_assignments.py` reads `pool-text-generating.csv` (line 14), which `make_pool.py --final` overwrites from the uncut `no_dataset` list. Write that CSV from the intersection. Do not run `make_pool.py --final` afterward.

5. **`--fetch` with `--as-of 2026-10-10` is safe on this date, and the pool is unusable without it. Severity: must fix before use.** `funnel.py` 587–591 refuses `--fetch` when today's UTC date is after `--as-of`, because the new files would be dated today and `load_cards` would ignore them. Today is 2026-10-10, so the guard allows the fetch. `hub.fill` (`hub.py` 464–475) writes new cache files dated that day. It does not move `CURRENT`. A later normal run of the same date will see the new parent cards and configs; models still at `no_dataset` return before those files are read, so this fetch does not by itself change `results/medical/2026-10-10/decisions.csv`. After UTC midnight on 2026-10-11 the same command exits 2. Fetch until `missing.csv` is empty, or until the only misses are gates, before anyone reads survivors.

6. **The regex class will drop children a reader would keep, and 633 of the 987 have an unregistered parent. Severity: must fix before use.** `parent_class` (`rules.py` 548–564) is yaml, then README, then a name token, and only a `parents.csv` row overrides it. Among the 987: 354 children have one of 37 registered parents, all `instruction`; 633 children have one of 217 parents with no row. Three of the 354 are children of `openai/gpt-oss-20b`. That row is `instruction` (`parents.csv`, the vendor post-training rule). The weight check runs first and the cached card is `other_dtype` (`BF16|U8`), so the funnel drops them anyway. The name regex did not. For the 633, with the cache as it is:

   | Stop under the real step-3 order | Children |
   |---|---:|
   | parent card not cached | 389 |
   | regex `finetune` | 71 |
   | regex `pretrained` | 58 |
   | regex `instruction` (config still missing) | 43 |
   | regex `not_stated` | 40 |
   | `no_root` | 12 |
   | parent README not cached | 8 |
   | `bin_unreadable` | 8 |
   | regex `unreadable` | 2 |
   | parent header not cached | 2 |

   The relaxed run would exclude the 171 children already classed `finetune`, `pretrained`, `not_stated`, or `unreadable`. The registry shows that rate is not safe to trust. Of 93 registered `instruction` parents that have a card and a README, the regex agrees on 74 and returns something else on 19 (10 `not_stated`, 7 `finetune`, 1 `pretrained`, 1 `conflict`). Inside the 171, `google/flan-t5-small` (11 children) and `google/flan-t5-large` (1) are `not_stated`, while `google/flan-t5-base` is already registered `instruction` on the sentence "fine-tuned with instructions" (`parents.csv` row for `google/flan-t5-base`). `facebook/bart-base` (37) and `microsoft/phi-1_5` (3, "has not undergone instruction fine-tuning") are pretrained on the README; dropping those matches step 3.

   The 389 missing cards include three Unsloth rehosts of parents the registry already calls `instruction`: `unsloth/Meta-Llama-3.1-8B-Instruct` (64 children; original `meta-llama/Llama-3.1-8B-Instruct`), `unsloth/Qwen3-8B` (58; original `Qwen/Qwen3-8B`), `unsloth/Olmo-3-7B-Instruct` (55; original `allenai/Olmo-3-7B-Instruct`). The funnel will not copy the original's class. `unsloth/Qwen3-8B` has no `instruct` / `chat` / `it` name token (`NAME_INSTR`, `rules.py` 450), so a thin README becomes `not_stated` and the child is dropped. The handoff's "a rehost takes the original's class" is applied in `build_parents.py` when an agent marks the row `rehost`. It is not applied by `funnel.py`.

   What to change, either ordering: fetch, run the relaxed funnel, send `parents_unregistered.csv` through the parent registry, rerun, and only then take survivors. That file already lists every parent that reached the class check without a row, including parents the regex rejected (`funnel.py` 499–502, written at 620–625). Or keep every `no_dataset` text-generating child whose parent has no `parents.csv` row, whatever the regex says, and let the registry remove it on the funnel rerun after admission. Register-first avoids searching parents a reader will class `pretrained`. Keeping unregistered children avoids missing `flan-t5-small` and `unsloth/Qwen3-8B`. Do not finalize the pool on the first relaxed run.

7. **Other models the survivor rule drops or keeps for the wrong reason. Severity: must fix before use for the shard names and the untagged configs; note for the rest.**

   - **Qwen3.5 shard names (must fix before use).** `rules.ROOT_CKPT` (`rules.py` 42) matches `model.safetensors` and `model-00001-of-00002.safetensors`. It does not match `model.safetensors-00001-of-00002.safetensors`. `full_precision` (`rules.py` 147–152) then returns `no_root` and never reads the dtype summary.    - **Empty `pipeline_tag` (must fix before use).** 236 of the 987 are untagged and have no `config.json`. `make_pool.py` 28 keeps them only until the fetch, and `--final` refuses to write the pool while any remain (line 36). ## (d) What the proposal does not take up

- `parent_discordant` is part of step 3 (`funnel.py` 412–427). The current medical run removes 12 models there (`counts.csv`). Almost none of the 987 have a child config, so that cut has not been measured. Some of the 987 will fail it after the fetch and should not be searched.
- The relaxed run fetches parent cards for every one-parent model that passes step 1 and is not vision, including token-classification and models that already have a dataset. That is extra Hub traffic. It is not a reason to skip the fetch for the real pool.
- `make_pool.py` and the handoff already exclude "tagged other" (2,888 of the 8,177 `no_dataset` rows: token-classification 1,612, text-classification 569, and the rest). The proposal's 5,289 correctly leaves those out. The relaxed survivor list puts them back if they pass step 3.
- A sweep is recomputed on whatever pool CSV is written (`make_dataset_assignments.py` 15–21). Cutting quantized and parent-less models will shrink some sweeps under the minimum of 5, and those models then get searched one by one. That raises the agent count relative to a sweep on the uncut pool. It does not drop a model.
- Safety did not search its whole pool. Section 4 of `docs/safety_FT_funnel/review-2026-10-09.md`: pool 3,144, agents 1–198 ran, agents 199–315 were not launched (1,164 models), and the sweep rule from the start would have been 97 agents rather than 315. A medical-versus-safety comparison of step-2 counts has that gap in it already.
- `SivaSai8143/pharma-tinyllama-non-instruction-merged` is classed `instruction` by the regex (1 child). That is the opposite error: the relaxed run would search a parent the name says is not instruction-tuned. The registry pass in finding 6 is what catches it. One child is not a reason to keep the regex.
