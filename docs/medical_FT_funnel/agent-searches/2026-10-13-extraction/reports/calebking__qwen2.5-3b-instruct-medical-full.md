## Record

The training set is the author's MedInstruct mix of BioInstruct and AlpaCare-MedInstruct-52k. The card says "Dataset: MedInstruct (combined from BioInstruct and AlpaCare-MedInstruct-52k)". The training notebook prints "Train Dataset Size: 53370", "Val Dataset Size: 2965", and the held-out test file is another 2965 lines. That mix is JSONL in the GitHub repo, not a Hub dataset, so it does not load from the Hub. BioInstruct is `bio-nlp-umass/bioinstruct` (25,005 English rows; "generated by OpenAI's GPT-4 engine") and the viewer loads. AlpaCare-MedInstruct-52k is `lavita/AlpaCare-MedInstruct-52k` (52,002 English rows) and the viewer loads. The xz97 MedInstruct card says those 52k instructions "are crafted by OpenAI's GPT-4 engine, and the responses are formulated by the GPT-3.5-turbo engine."

The objective is supervised instruction tuning. The card says "Method: Full instruction tuning". The notebook masks every token before the assistant reply "so loss is only calculated on the assistant reply" and trains with transformers `Trainer` for 3 epochs, 5,004 steps, learning rate 2e-5, and a stated batch of 8 times 4 accumulation steps. Update scope is full: "full fine-tuning trains all model parameters" and the notebook prints "trainable%: 100.00%". The base is loaded "in bfloat16", not as a quantized checkpoint. There is no LoRA rank. The card also says "Framework: PEFT 0.18.1", but this notebook does not import PEFT.

The parent is Qwen/Qwen2.5-3B-Instruct. The card says "Base model: Qwen/Qwen2.5-3B-Instruct" and the notebook sets `model_name = "Qwen/Qwen2.5-3B-Instruct"`. Those agree. The notebook prints 3,085,938,688 parameters, all trainable. The Hub safetensors total is the same count.

The use claim is weak. The card says the model was "Full fine-tuned Qwen2.5-3B-Instruct on medical instruction datasets to improve medical quantitative reasoning." That is a thesis experiment, not a claim that the model gives advice, a diagnosis, or treatment to a person. The card has no warning about medical use.

A purpose is stated: "to improve medical quantitative reasoning." No audience is named. No function from the closed list is claimed. The GitHub README frames the work as a master's thesis "to investigate whether smaller models could improve at medical quantitative reasoning."

The clinical task named for training is medical quantitative reasoning, which is not one of the named task labels, so it is recorded as other. MedQA-USMLE-4-options is an evaluation only. The README says variants "were evaluated" on MedCalc-Bench-v1.0, MedQA-USMLE-4-options, and a custom MedInstruct test set. The saved MedQA run for this local checkpoint reports accuracy 0.350 on 1,273 questions. The specialty is general medicine: the card says "medical" and names no field. The card calls the model a "Text generation / Instruction fine-tuned language model" and does not show a sample of what it writes.

Serving is text only. A chat template is in the repository and in the Hub API, and the default system line is "You are Qwen, created by Alibaba Cloud. You are a helpful assistant." The training notebook used an empty system prompt. generation_config.json sets do_sample true, temperature 0.7, top_p 0.8, top_k 20, and repetition_penalty 1.05. Context length in config.json is 32,768. The license name on the card is qwen-research. No paper names this repository. The inventory row (full fine-tune, MedInstruct, Qwen/Qwen2.5-3B-Instruct) matches the card and the notebook.
