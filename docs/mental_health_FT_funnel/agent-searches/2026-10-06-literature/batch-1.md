## 1. AIMH/SQPsych-8b-gemma-Qwen

### Sources

- Model card, cached 2026-10-05: `revision_3_experiments/hf_inventory/cache/readmes/AIMH__SQPsych-8b-gemma-Qwen__2026-10-05.md`. Names this repo id. Authors on the card: Doan Nam Long Vu and collaborators.
- Preprint, arXiv 2510.25384, HTML retrieved 6 Oct 2026: https://arxiv.org/abs/2510.25384 . Authors: Doan Nam Long Vu, Rui Tan, Svenja Jule Francke, Lena Moench, Daniel Woiwod, Florian Thomas-Odenthal, Sanna Stroth, Tilo Kircher, Christiane Hermann, Udo Dannlowski, Hamidreza Jamalabadi, Simone Balloccu, Shaoxiong Ji. Does not print `AIMH/SQPsych-8b-gemma-Qwen`.
- Project page, same authors' site: https://ai-mh.github.io/SQPsych.html . Lists `AIMH/SQPsychLLM-8b-gemma-Qwen`, which is not this repo id.
- Training script: https://github.com/AI-MH/questionnaire2dialogue/blob/main/src/finetune.py . Does not print this repo id. Hard-codes a Llama base model.
- Dataset API: https://huggingface.co/api/datasets/AIMH/SQPsychConv_gemma and https://huggingface.co/api/datasets/AIMH/SQPsychConv_gemma_finetune . Created 2025-10-29.

### Training record

**(a) Objective.** Card says: "This checkpoint is **Qwen2.5-7B-Instruct** supervised-fine-tuned on **SQPsychConv (Gemma)**." That is supervised fine-tuning. The script for the family uses `SFTTrainer`, but its base model line is `base_model = "meta-llama/Meta-Llama-3-8B-Instruct"`. Paper says: "we fine-tune Llama3-8B-Instruct ... on each portion of the synthetic dataset" and "SQPsychLLMmistral corresponds to LLaMA-8B-Instruct, fine-tuned on dialogues produced by mistral." The paper does not say this Qwen checkpoint was trained with preference optimization, reinforcement learning, or a distillation loss. It uses "distilled" for the synthetic corpus, then "fine-tune."

**(b) Parameter-update scope.** Not stated anywhere found for this Qwen checkpoint. Paper says, about a Llama Psych8k baseline and then the Llama SQPsychLLM runs: "we perform a full BF16 fine-tuning of Llama3-8B-Instruct on Psych8k, using the same hyperparameters as CAMEL (5 epochs, learning rate 2e-4). We use the same hyperparameters for finetuning SQPsychLLM." The script loads Llama 3 8B Instruct in bfloat16 and has no `LoraConfig`. Hub siblings for this repo (cache `2026-10-05__017.csv`): `model.safetensors` only. No `adapter_config.json`. That shows a full weights file was uploaded. It does not say whether training updated every weight.

**(c) Training data.** Card says the data are `AIMH/SQPsychConv_gemma`, "synthetic therapist-client conversations generated by `google/gemma-3-27b-it`," from "de-identified structured profiles and questionnaire scores (BDI, HAM-D) from the cohort of Kircher et al. (2019)," and "The instruction-formatted split used for training is `AIMH/SQPsychConv_gemma_finetune`." Language on the card: English. Dataset API: `AIMH/SQPsychConv_gemma` has 1,837 train and 253 test dialogues; `AIMH/SQPsychConv_gemma_finetune` has 28,434 train and 3,931 test rows with fields `input`, `output`, and `instruction`. Project page: "AIMH/SQPsychConv_gemma | 2.09k | google/gemma-3-27b-it" and "AIMH/SQPsychConv_gemma_finetune | 32.4k". Paper: "We obtain 2090 conversations per model" and the Gemma corpus has 71,000 utterances. Provenance: synthetic, generator `google/gemma-3-27b-it`, conditioned on real de-identified questionnaire numbers. The dialogues are not human therapy transcripts.

**(d) Base model.** Card YAML and prose: `Qwen/Qwen2.5-7B-Instruct`. That id is the instruction-tuned Qwen2.5 checkpoint. Paper and `finetune.py` name `Llama3-8B-Instruct` / `meta-llama/Meta-Llama-3-8B-Instruct` as the model that was fine-tuned. Project page row: "AIMH/SQPsychLLM-8b-gemma-Qwen | 8B | SQPsychConv (Gemma) (Finetune on Qwen2.5-7B-Instruct)."

**(e) Hyperparameters.** Not stated anywhere found for this Qwen file. The paper's "5 epochs, learning rate 2e-4" and the script's `learning_rate=2e-5`, `num_train_epochs` default 5, `per_device_train_batch_size=2`, `gradient_accumulation_steps=16` are attached to the Llama SQPsychLLM recipe. No batch size or hardware is stated for this checkpoint.

**(f) Evaluation.** Not stated anywhere found for this checkpoint. The paper reports CounselingBench (1,612 questions), CBT-Bench (146, 184, and 112 items), an LLM-judge panel, and therapist preference ratings for SQPsychLLM, which the paper defines as Llama 3 8B Instruct. Table 3 includes `SQPsychLLMgemma`. Those scores are not labeled as this Qwen file.

### Discrepancies

1. The card and the project-page row say the student model is Qwen2.5-7B-Instruct. The paper and `src/finetune.py` fine-tune Llama 3 8B Instruct.
2. The project page prints `AIMH/SQPsychLLM-8b-gemma-Qwen`. This repository is `AIMH/SQPsych-8b-gemma-Qwen`.
3. The project page calls the Qwen file "8B". The base model is the 7B Qwen2.5 Instruct checkpoint.
4. Inventory `methods` is `sft`, which matches the card's "supervised-fine-tuned." Inventory `datasets` is only `AIMH/SQPsychConv_gemma`. The card says training used `AIMH/SQPsychConv_gemma_finetune` (28,434 train rows). The paper's Gemma utterance count is 71,000.
5. Paper learning rate 2e-4 versus script learning rate 2e-5. Neither source says those numbers were used for this Qwen file.

### Confidence

Medium. The card and the project page agree that a Qwen2.5-7B-Instruct model was fine-tuned on the Gemma SQPsychConv corpus, but the project page uses a different repository string, and the paper and the released script both train Llama 3 8B Instruct.

### Training record

**(a) Objective.** Not stated anywhere found. Card says the model "was fine-tuned using the Unsloth framework" and "Parameter-Efficient Fine-Tuning was performed using LoRA." It does not say supervised fine-tuning, preference optimization, reinforcement learning, or continued pre-training. The dataset is question-answer text, which does not by itself name the loss.

**(b) Parameter-update scope.** Card says: "This model is an 8-bit LoRA fine-tune" and lists `Rank (r): 16`, `LoRA Alpha (lora_alpha): 16`, target modules `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`, `lora_dropout` 0.1, `bias` none, `use_rslora` True. **(c) Training data.** Card YAML: `Daemontatox/Psy-Data-books`. Card prose: "professional psychiatric literature, textbooks, and clinical guidelines." Dataset card says: "Psy-Data-Books is one of the largest synthetic datasets of psychology and medical conversations, generated from verified medical and psychology literature" and "Generated using DS_Creator." Hub row count: 122,324. Language tag: English. Columns on the viewer: `user_message`, `assistant_message`, `metadata`. Row 0 and row 60,000 both have `generation_metadata.model` = `deepseek-chat` and `provider` = `deepseek`. Those two rows are not a scan of all 122,324 rows. Source PDFs named in those rows include a textbook filename with `libgen.li` in it. The dataset citation URL still says `https://huggingface.co/datasets/Daemontatox/Psy-Data-books`, and the API returns id `Compumacy/Psych_data`.

**(d) Base model.** Card: `unsloth/Qwen3-32B`. Unsloth's card YAML `base_model` is `Qwen/Qwen3-32B`, and the Hub tag is `base_model:finetune:Qwen/Qwen3-32B`. Qwen's card says: "Training Stage: Pretraining & Post-training" and describes instruction-following and a switch that "align[s] its functionality with the previous Qwen2.5-Instruct models." It is the post-trained Qwen3-32B checkpoint, not a separate base-only id. There is no `-Instruct` suffix on this id.

**(e) Hyperparameters.** Card says: epochs 1, learning rate 1e-6, optimizer `adamw_8bit`, per-device batch size 2, gradient accumulation 8, "single NVIDIA A100 80GB PCIe GPU." No other source states these numbers.

**(f) Evaluation.** Not stated anywhere found. The card's `model-index` results list is empty.

### Discrepancies

1. Card describes the data as textbooks and guidelines. The dataset card and the stored rows are synthetic question-answer pairs. Two sampled rows name the generator `deepseek-chat`.
2. Card says 8-bit LoRA. The upload is a full 32B BF16 checkpoint with no `adapter_config.json`, while the Hub tag says `adapter`.
3. Inference snippet loads `Daemontatox/Compumacy-Experimental_MF`, not `Compumacy/Psych_Qwen_32B`.
4. YAML dataset id `Daemontatox/Psy-Data-books` resolves to `Compumacy/Psych_data`.
5. Inventory `methods` is `lora`, `datasets` is `Daemontatox/Psy-Data-books`, and `parent` is `unsloth/Qwen3-32B`. Those match the card. The inventory does not record rank, 8-bit, or the full-file upload.
6. Featherless repeats the card. It does not add a method.

### Confidence

Medium that the card is the author's account of a LoRA run on this dataset and this base model. The uploaded files are a full checkpoint, the inference example names a different repository, and no script was found, so the rank and the 8-bit claim are card-only.
