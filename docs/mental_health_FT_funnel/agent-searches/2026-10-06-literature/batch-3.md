### Training record

**(a) Objective.** Supervised next-token fine-tuning. Script says: `from trl import SFTTrainer, SFTConfig` and builds `trainer = SFTTrainer(...)` with `dataset_text_field="text"`. The text is a Mistral chat string: `"<s>[INST] {system}\n\n{user} [/INST] {assistant} </s>"`. The script does not set a preference loss, a reward model, or `completion_only_loss`. Card says, in the pipeline diagram: "QLoRA Fine-Tuning / SFTTrainer · 1 Epoch."

**(b) Parameter-update scope.** QLoRA, then a merge. Script says: `BitsAndBytesConfig(load_in_4bit=cfg.use_4bit, ... quant_type "nf4", use_double_quant True)` and `prepare_model_for_kbit_training`. `LoraConfig` uses `r=cfg.lora_r` (16), `lora_alpha` 32, dropout 0.05, `task_type=TaskType.CAUSAL_LM`, targets `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`. Executed output: "Trainable parameters: 41.94M (1.104%)" and "trainable params: 41,943,040 || all params: 7,289,966,592". Later cell: `merged_model = peft_model.merge_and_unload()` and "Merged model saved! Total size: 13.50 GB". Card says: "Fine-Tuning Method | QLoRA (4-bit NF4 Quantization)" and "LoRA Config | r=16 · α=32 · dropout=0.05" and "Merge into Base Model / 13.5 GB". The saved notebook's upload cells (`PUSH_ADAPTER_ONLY = False`, upload of `merged_model`) have no execution count. The Hub file list is the full fp16 model, not an adapter.

**(c) Training data.** Two Hub datasets.

- CounselChat, `nbertagnolli/counsel-chat`. Dataset card says: "Scrape of Counselchat.com's forum" and "expert responses by licensed clinicialns to questions posed by individuals." Language: English. Notebook output: "Rows: 2,775" then "CounselChat: 2,775 → 2,598 samples" after a length filter.
- PHR, `vibhorag101/phr_mental_therapy_dataset`. Dataset card says: "This dataset is a cleaned version of nart-100k-synthetic" and "The data is generated synthetically using gpt3.5-turbo" and `num_examples: 99086`. Language: English. Notebook output: "Rows: 99,086" then "PHR Therapy: 99,086 → 25,838 samples" after a length filter (`min_len=100`). The sample still starts with a Llama-2 `<<SYS>>` block. The PHR rows were not rewritten into the Mistral template. That template was applied only to CounselChat.

Executed combination: "Combined total: 28,436 samples", then "Capped to 15,000 samples", then "Train: 14,250 | Val: 750". A later cell takes the first half of that train split: "Half train: 7,125" and "Half eval: 375". The `SFTTrainer` that actually ran was given `train_dataset=train_half` (7,125) and `eval_dataset=eval_half` (375). Output: "Train samples: 7,125".

**(d) Base model.** Script says: `MODEL_ID = "mistralai/Mistral-7B-Instruct-v0.3"` and the comment "Instruction-tuned, strong reasoning, 32K context." Card says the same id. Inventory `parent_class_evidence`, quoting the base model's readme: "The Mistral-7B-Instruct-v0.3 Large Language Model (LLM) is an instruct fine-tuned version of the Mistral-7B-v0.3." Uploaded `config.json` has `"_name_or_path": "mistralai/Mistral-7B-Instruct-v0.3"` and `"transformers_version": "4.44.2"`, which is the version the notebook installs.

**(e) Hyperparameters of the run that finished.** Cell 19, which replaced an earlier 3-epoch config, says: `num_train_epochs=1`, `per_device_train_batch_size=2`, `gradient_accumulation_steps=8`, `learning_rate=2e-4`, `lr_scheduler_type="cosine"`, `warmup_ratio=0.05`, `optim="paged_adamw_32bit"`, `max_seq_length=512`, `packing=False`, `fp16=True`. The step count implied by `train_steps_per_second = 0.025` over that runtime is about 445 steps, which matches `7125 // (2 * 8)`. An earlier cell had printed an effective batch of 32 under the pre-override config (batch 1, accumulation 16, two GPUs). That trainer was replaced before `trainer.train()`.

**(f) Evaluation.** Script and output: perplexity on 200 rows of `eval_dataset`, "Running perplexity: 2.359", then 2.439, 2.438, and "Final Perplexity: 2.451". Mean NLL 0.8966.
